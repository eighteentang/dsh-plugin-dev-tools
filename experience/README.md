# 开发经验库 —— 使用与贡献说明

这个目录里只有一份文件：[经验库.md](经验库.md)。它是**随插件分发**的共享知识库。

---

## 它解决什么问题

开发 DSH 插件时会遇到很多**文档里没写、只能踩出来**的坑。比如：

- 复制到剪贴板为什么静默失败
- 为什么改了插件代码、重启插件却没生效
- 为什么自己建的 agent 收到消息却永远不执行
- 为什么悬浮框会疯狂闪烁

每个人踩一遍、各自花几小时，是纯浪费。**所以把结论攒成这份文件，
跟着插件一起分发** —— 装插件的人自动获得所有前人的经验。

**它是累积的**：用的人越多、提交的经验越多，条目越多，后来的人越省事。

---

## 作为使用者：怎么更新

1. 在插件的设置页看**当前版本**（比如「14 条，更新于 2026-09-26」）
2. 去项目 GitHub 看这份文件有没有更新的
3. 有更新的就**下载、直接替换掉插件文件夹里的这一份**（路径见下）
4. **重启客户端**生效

替换路径：

```
<插件文件夹>/experience/经验库.md
```

> 💡 **为什么要看版本而不是只看日期**：文件顶部有一段元信息，里面有
> `entries`（条数）和 `fingerprint`（内容短哈希）。
> 别人**修正**了一条旧经验时条数不变、日期也可能没更新，但指纹会变 ——
> 只看日期会漏掉这种更新。
>
> 插件设置页会显示你当前用的是哪一版、以及**头部与实际内容是否一致**
> （不一致说明有人改了内容但忘了更新头部）。

## 作为贡献者：怎么加一条经验

1. **在文件末尾追加一条**，格式照抄现有的：

   ```markdown
   ## E15 · 一句话标题（写症状，不要写"要注意 XX"）

   - **症状**：你会看到什么现象
   - **解法**：该怎么做
   - **细节**：可选补充（为什么、怎么查、实测案例）
   ```

2. **更新文件顶部的元信息**：

   ```json
   {
     "schema": 1,
     "version": "2026.10.01",        ← 改成本次日期
     "entries": 15,                   ← 改成实际条数
     "updatedAt": "2026-10-01",       ← 改成本次日期
     "fingerprint": "xxxxxxxx"        ← 新的内容哈希
   }
   ```

   指纹算法（8 位小写十六进制）：

   ```
   sha256( 每条按 "id|title|symptom|solution" 拼一行、用 \n 连接 ).slice(0, 8)
   ```

   算不出来也不打紧 —— **只填 `entries` 与 `updatedAt`**，插件会提示
   "头部与实际不一致"，用户可以据此判断。**但别填错条数**，那比不填更让人困惑。

3. **提 PR**。

### 写经验的标准

| 要 | 不要 |
|---|---|
| 写**具体症状**（"点复制按钮没反应，粘贴是空的"） | 写原则（"要注意剪贴板权限"） |
| 写**可执行的解法**（"照抄 `writeClipboard()`"） | 写方向（"建议参考框架实现"） |
| 带上**查法/实测案例** | 只给结论 |
| 一条一个坑 | 一条混好几个问题 |

**原则 AI 本来就知道，具体症状才能让它对上号** —— 这是这份文件存在的意义。

---

## 格式约定的技术原因

`经验库.md` 用的是**固定格式**（`## E<n> · 标题` + `- **症状**` / `- **解法**` / `- **细节**`）。
这不是为了好看，而是因为插件要**解析它并把索引注入到 AI 的提示词里**：

- 每条只注入**症状与解法的前 100 字**
- 全文留在文件里，AI 需要细节时自己去读

所以：**改格式会让解析失败**。加条目可以，改结构不行。

顶部用 HTML 注释（`<!-- ... -->`）装元信息，是因为它在 markdown 渲染时不可见，
但机器可读、GitHub 上也人读得到。
